# Whiteboard Patterns

Choose the smallest pattern that explains the content clearly.

## Staged Flow

Use for processes, workflows, launch plans, review loops, or troubleshooting.

- Layout: left-to-right stages with 3-6 columns.
- Grouping: each stage contains 1 hero node and 1-3 supporting nodes.
- Connectors: only stage-to-stage main path plus rare exception arrows.
- Good additions: owner badges, risk chips, time labels.

## Swimlane Flow

Use when multiple roles or systems interact.

- Layout: lanes by actor/system; time moves left to right.
- Grouping: each lane has aligned actions.
- Connectors: cross-lane arrows show handoffs.
- Avoid: too many diagonal arrows; merge repeated back-and-forth into one interaction group.

## Layered Architecture

Use for system architecture, data flow, API integration, or platform maps.

- Layout: top-to-bottom layers such as user, product, service, data, governance.
- Grouping: modules sit inside layer frames.
- Connectors: arrows show request/data direction; label only important protocols or payloads.
- Emphasis: highlight critical path and failure points.

## Comparison Matrix

Use for before/after, option A/B/C, vendor choice, or strategy tradeoffs.

- Layout: columns are options; rows are criteria.
- Grouping: shared criteria at left; option summaries at top.
- Emphasis: use badges for winner, risk, and open question.
- Avoid: long prose in cells.

## Roadmap Timeline

Use for milestones, phased delivery, quarters, or migration plans.

- Layout: horizontal time axis with phase bands.
- Grouping: milestones on the axis, workstreams below.
- Emphasis: decision gates and risks use accent colors.
- Avoid: putting every task on the main line.

## Funnel

Use for conversion, drop-off, recruiting, onboarding, or operational throughput.

- Layout: vertical or horizontal narrowing stages.
- Grouping: stage label, metric, and leakage note.
- Emphasis: largest loss or bottleneck.
- Avoid: using a funnel when there is no quantitative narrowing.

## Driver Tree

Use for cause analysis, KPI decomposition, business levers, or strategy pillars.

- Layout: goal on the left/top; branches split into drivers and actions.
- Grouping: 2-4 primary drivers; 2-4 sub-drivers each.
- Emphasis: mark controllable vs external factors.
- Avoid: more than 3 hierarchy levels unless it becomes a mind map.

## Executive Strategy Map

Use for planning docs, leadership readouts, and product strategy.

- Layout: north-star objective at top; 3-5 pillars below; proof/risk layer at bottom.
- Grouping: each pillar has bet, mechanism, and evidence.
- Emphasis: decisions and asks are visually distinct.
- Avoid: decorative storytelling without concrete mechanisms.

## Product Evolution Storyboard

Use for explaining product maturity, current-to-future evolution, and staged vision.

- Layout: wide canvas with 3-5 tall phase columns.
- Grouping: each phase contains user pain, product expression, and capability/ideal-state interpretation.
- Emphasis: make the target/future state visibly richer than the current state.
- Avoid: pure timeline treatment when the board needs to compare product experience states.

## Minimal Three-Step Pipeline

Use for a simple method where three inputs or steps produce an outcome.

- Layout: three equal cards in one row, with optional evidence/mockup blocks below.
- Grouping: one card per step; no nested substructure unless essential.
- Emphasis: symmetry, calm spacing, and concise labels.
- Avoid: adding arrows, chips, or colors when the sequence is already obvious.

## Clear Bridge Decision Map

Use for routing multiple inputs and constraints into scenario-specific handling and one final output.

- Layout: inputs at top, constraints/assets in the middle, scenario cards in the center, output band at bottom.
- Grouping: 3 central scenario cards work well; label them A/B/C.
- Emphasis: final output band and key scenario split.
- Avoid: connecting every dependency; show the main logic path only.

## Capability Coverage Roadmap

Use for showing which AI/product/design capabilities cover which workflow stages.

- Layout: horizontal workflow stages, colored capability chips, and a cross-cutting foundation band.
- Grouping: phases across the top/middle; capabilities underneath each phase.
- Emphasis: color legend and stage coverage.
- Avoid: more than three semantic chip colors.
